# 多维表图片导出 Excel（飞书多维表自定义插件）

一个**纯前端、可部署到任意静态网站**的飞书多维表插件。把它作为「自定义插件」填上网址即可使用：自动读取当前多维表的每一行，把指定**图片 / 附件字段**导出成带图的 Excel——多维表的一行对应 Excel 的一行，图片落在对应列里。

- 纯前端运行，无需后端服务器
- 附件字段 → 单元格内嵌图片；其它字段 → 文字
- 自动分页读取（适配大表），并发下载，带进度
- 图片优先取原图；若跨域被拦，自动回退缩略图（base64，不受 CORS 影响）
- 可选「图片 ZIP」模式：按你指定的文字列命名，把每行每张图打包成 ZIP 下载
- 可选「仅导出当前视图」：只导出飞书当前视图下筛选后的记录
- 可选「导出后标记」：导出完成后自动勾选某复选框字段（或一键新建「已导出」字段）标记已处理行

## 一、在飞书里配置为「自定义插件」

> 飞书后台界面可能随版本调整，以下为通用流程。

1. 打开 [飞书开放平台](https://open.feishu.cn/) → 创建**企业自建应用**。
2. 给应用添加能力：**多维表格**（在「添加应用能力」里找「多维表格 / Bitable」）。
3. 在该能力配置中，添加**自定义插件 / 网页插件**，把本项目的部署网址填到「主页 URL / 插件 URL」。
4. 发布应用版本，并让多维表管理员把该应用加入多维表的协作者。
5. 在目标多维表里：右上角 `...` → 扩展 / 插件 → 添加插件 → 选「自定义插件」→ 粘贴本页面网址 → 启用。

插件打开后即为当前表环境，可直接使用。

## 二、部署到静态网站

插件本质是静态文件，**任何能托管 HTTPS 静态资源的地方都可以**：

### 方式 A：GitHub Pages（推荐）
1. 把这些文件推到一个仓库（如 `feishu-bitable-image-excel`）。
2. 仓库 Settings → Pages → Source 选 `main` 分支根目录 → Save。
3. 等待片刻，访问 `https://<你的用户名>.github.io/<仓库名>/`。
4. 把这个地址填到飞书自定义插件的网址里。

> 本项目全部使用相对路径，GitHub Pages 的 `/<仓库名>/` 子路径下也能正常加载。

### 方式 B：任意静态托管
Vercel / Netlify / 对象存储 + CDN / 内网静态服务器均可。把本目录整体上传，访问 `index.html` 的 HTTPS 地址即可。

### 方式 C：本地预览（仅看 UI，无法连飞书）
```bash
cd 本目录
python -m http.server 8000
# 浏览器打开 http://localhost:8000
```
> 注意：飞书要求自定义插件网址为 **HTTPS**，且必须在飞书多维表内打开才能真正读到数据；普通浏览器打开只会显示环境提示。

## 三、使用步骤

1. 在飞书多维表里打开本插件，状态栏显示「已连接：<表名>」。
2. 在「字段选择」里勾选要导出的列（📎 图片字段默认勾选，会导出为图片）。
3. 点「加载数据」，确认行数。
4. 点「导出 Excel」，浏览器会下载一个 `.xlsx`，每行对应多维表一行，图片嵌入在对应列。
5. 需要「按文字列命名图片并打包」时：在「图片命名列」里选一个文字列（默认主键），点「导出图片 ZIP」，每行每张图会以 `<该列值>__<字段名>_<序号>` 命名并打包成 `.zip` 下载（同样支持「仅导出当前视图」和「导出后标记」）。

选项说明：
- **图片显示宽度**：Excel 里图片的显示像素宽（原图数据仍完整保留，只是显示缩放）。
- **并发下载数**：同时下载的图片数量，网络好可调大。
- **未勾选字段也一起导出为文字列**：勾选后，未单独勾选的字段也会作为文字列附带导出。
- **图片命名列（用于 ZIP）**：选一个文字列作为 ZIP 模式下的图片文件名前缀；文件名格式为 `<该列值>__<字段名>_<序号>`，同名自动加后缀，非法字符替换为 `_`。
- **仅导出当前视图**：勾选后，只导出飞书当前视图（已筛选 / 排序）下的记录，而不是整张表。
- **导出后标记「已导出」**：下拉选择「不标记 / 某个复选框字段 / ＋新建「已导出」复选框字段」。选择后，每次导出完成会自动把已导出的行在该字段勾选为 true（新建模式会在表里新增一个名为「已导出」的复选框字段）。

## 四、技术要点

- 通过官方 SDK `@lark-base-open/js-sdk` 的桥接读取数据（`bitable.base`）。
- 附件单元格只含 `token`，需用 `table.getCellAttachmentUrls(tokens, fieldId, recordId)` 换取临时下载 URL。
- 分页用 `table.getRecordsByPage({ pageSize, pageToken })`，逐页读完所有行。
- 图片清晰度（见「图片设置 → 图片质量」）：
  - **缩略图（默认·最快）**：直接调用 `table.getCellThumbnailUrls(...)` 拿飞书返回的 base64 缩略图（最长边 ≤ 1280px），不跨域、不逐个联网，最快最稳。
  - **高清原图**：调用 `table.getCellAttachmentUrls(...)` 拿附件直连 URL，本地 `fetch` 取原图嵌入 Excel；若被飞书 CDN 的 CORS 拦截，则自动回退上面的缩略图。整个过程不借助任何代理 / Worker。
- 图片已按实际尺寸设置列宽与行高，贴在对应单元格内（Excel 中图片为浮动对象，默认会随单元格位置对齐，但不会随列宽缩放）。
- ExcelJS 已随仓库打包（`vendor/exceljs.min.js`），离线也能用。

## 五、已知限制 / 注意

- **图片清晰度（重要）**：默认「缩略图」模式下，图片经 `getCellThumbnailUrls` 取飞书返回的 base64（最长边 ≤ 1280px），不跨域、最快最稳。若切到「高清原图」，插件会用 `getCellAttachmentUrls` 拿附件直连 URL 本地 `fetch` 取原图；飞书附件原图存于飞书 CDN，前端 `fetch` 常被 CORS 拦截，此时自动回退缩略图——这是飞书前端 SDK 的硬限制，不是 bug。导出完成后日志会显示「原图 N / 缩略图 M」，若选了原图却 N=0 即说明被 CORS 拦截。要拿到**真·原图分辨率**且稳定可用，需走飞书服务端 API（用 `tenant_access_token` + 附件下载接口，需自建轻量后端代理），前端无法保证。
- **显示宽度**：导出的图片「显示尺寸」按你设定的宽度缩放，图片数据本身仍是取到的真实分辨率（原图或缩略图），不会被二次压缩；小图不会被拉伸放大（已做防放大）。
- **高级权限**：若多维表开启高级权限，附件接口可能需要 `extra` 鉴权；插件运行在已授权的飞书环境内，通常已自动处理。
- **单行多图**：一个单元格里有多个附件时，会在该字段右侧自动多预留几列依次摆放。
- **单元格大小**：图片过多/过大时 xlsx 体积会变大，属正常现象。
